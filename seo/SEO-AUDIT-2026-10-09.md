3. Les événements passés/infos retirées de la sélection restent traçables ; leur ancienne page devient noindex au lieu de représenter un futur événement.
4. Slug stable à travers les générations (mapping conservé), échappement systématique des contenus.
5. Ne jamais effacer les exports métier pour économiser des octets.
6. Zéro API ou prestataire payant, et aucune exécution GitHub Actions ajoutée.

### Limitations importantes avant fusion

**Les scripts Python `scripts/rebuild_seo.py` et `scripts/check_seo.py` présents dans le dépôt n'ont pas encore été exécutés sur une copie intégrale du dépôt.** Les métadonnées ont été inspectées, mais la validation syntaxique complète de ces scripts et le fonctionnement navigateur sont à confirmer avant de fusionner. Ne pas présenter le déploiement comme prêt à 100 %.

- Les pages actuelles restent lourdes : la séparation du JS et des bases n'a pas encore été faite ; on évite de casser les filtres et les favoris sans tests.
- Écotank conserve deux H1 dans ses deux écrans ; correction après vérification de l'affichage et de la navigation.
- Les événements sont des instantanés publiés à partir de la base du 9/10/2026 ; la régénération doit être exécutée avant diffusion et périodiquement après pour éviter la péremption.
- Les dates annoncées ne signifient pas automatiquement confirmation finale par l'organisateur.
- Les pages événements ne comportent pas encore de JSON-LD `Event` ; mieux vaut attendre une validation complète des données et des exigences Google.
- Open Graph ne comporte pas encore `og:image` de partage ; favicon créé.
- Aucune mesure Lighthouse, Core Web Vitals, accessibilité clavier, pertinence en résultats Google ni contrôle exhaustif des liens sortants n'a pu être effectuée en navigateur réel.
- GitHub Pages ne fournit pas de 301 configurables arbitraires : migration à vérifier après branchement du domaine, sans promettre l'absence absolue de pertes SEO.
- `robots.txt` sous un sous-chemin GitHub Pages ne s'applique pas à la racine du domaine `github.io`. Sur le domaine personnalisé, il deviendra une politique d'exploration de la racine.

### Avant publication : checklist d'intégration hors GitHub Actions

1. Cloner la branche localement ou dans un environnement de test. Ne pas modifier `main`.
2. Lancer `python -m py_compile scripts/rebuild_seo.py scripts/check_seo.py scripts/site_quality.py`.
3. Lancer `python scripts/rebuild_seo.py`, puis `python scripts/site_quality.py` et `python scripts/check_seo.py`.
4. Inspecter le `git diff` et vérifier l'intégrité des exports : Activikids 1 141 événements, Écotank au moins 803 pistes, Cogito au moins 349 entrées.
5. Tester sur le navigateur desktop/mobile : boutons, filtres temporels, favoris et données locales, écran administratif Écotank et liens depuis les moteurs.
6. Vérifier des fiches prises au hasard, et des changements de date : aujourd'hui, date passée, annulation, sources mortes.
7. Confirmer absence de secrets/données privées et de liens cassés. Mesurer performances et accessibilité avant/après en conditions réelles.
8. Ne fusionner que si les tests passent ; ne pas lancer les workflows de publication tant que le quota Actions doit être ménagé.

### Après achat du domaine

1. Déclarer le domaine personnalisé dans GitHub Pages ; régler les enregistrements DNS, contrôler la propriété si nécessaire, activer HTTPS.
2. Remplacer `site_base_url` dans `seo/site.json` par l’URL HTTPS définitive avec `/` final.
3. Exécuter localement les trois commandes de génération/qualité ci-dessus ; vérifier les liens et les canonical, particulièrement le fichier `404.html`.
4. Publier uniquement la version validée.
5. Ajouter le domaine à Google Search Console, vérifier la propriété et soumettre `https://[domaine]/sitemap.xml`.
6. Contrôler les anciennes adresses GitHub Pages, les anciennes URL individuelles, les 404, l’indexation et les redirections éventuelles durant les semaines suivantes.
