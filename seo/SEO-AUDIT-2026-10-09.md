## Priorités
- P0 : fiches HTML autonomes réellement utiles, accessibles sans JS ; éviter la publication de pistes non vérifiées et d'événements expirés.
- P0 : lier les fiches à des hubs découvrables depuis les moteurs et le portail.
- P1 : base URL centralisée ; canonical, Open Graph, sitemap ; intégrité des sources et conservation des anciennes données.
- P1 : réduire le poids initial en séparant les données du rendu (intervention délicate à traiter séparément).
- P2 : iconographie, métadonnées de partage, enrichissements JSON-LD Event après validation factuelle.
- P3 : polissage graphique.

## Règles éditoriales pour les fiches
1. Un événement daté doit être à venir, descriptif et sourcé ; ne pas publier une prévision saisonnière comme une date certaine.
2. Un avantage Écotank n'est jamais déclaré acquis : les conditions et l'éligibilité restent à faire confirmer.
3. Les événements passés/infos retirées de la sélection restent traçables ; leur ancienne page devient noindex au lieu de représenter un futur événement.
4. Slug stable à travers les générations (mapping conservé), échappement systématique des contenus.
5. Ne jamais effacer les exports métier pour économiser des octets.
6. Zéro API ou prestataire payant, et aucune exécution GitHub Actions ajoutée.

## Après achat du domaine
1. Configurer le domaine personnalisé GitHub Pages et ses DNS selon GitHub ; attendre puis activer HTTPS.
2. Mettre à jour uniquement `seo/site.json` avec l'URL de base HTTPS.
3. Régénérer les pages et le sitemap, puis vérifier les canonical, OG et les chemins relatifs.
4. Mettre à jour Search Console, prouver la propriété et soumettre le sitemap.
5. Tester l'ancienne URL et les anciennes fiches, puis documenter les éventuelles limites de redirection de GitHub Pages.

**Attention** : un robots.txt stocké sous le chemin d'un projet GitHub Pages n'est pas le robots.txt de la racine de l'hôte github.io. Le fichier prend son sens à la racine du futur domaine personnalisé.

## Déploiement
Cette branche de préparation n'est pas destinée à être fusionnée aveuglément. Vérifier le build SEO, les liens internes, les filtres, les favoris locaux et les conditions de publication de chaque moteur. Ne lancer ni Actions ni PR par défaut tant que le quota est contraint.
